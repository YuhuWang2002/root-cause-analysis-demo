# 设计文档
## 设计目的
本系统希望演示一个根因分析的标准流程，从数据采集、数据处理、因果分析、根因识别等方面，展示一个完整的根因分析过程。

  1、 “用户需要做什么”  
      定义分析场景，对应功能：新建项目
  2、 “需要的数据来自哪里”
      定义数据来源，对应功能：添加数据源
  3、 “用户如何与数据信息交互”
      定义如何获取数据，需要哪些表，对应功能：配置需要读取的数据的权限，哪些表，哪些字段
  4、 “需要向用户提供什么样的结构化数据资产”
      定义取的数据应该转换为什么样的结构化数据，对应功能：获取数据并且转化存储
  5、 “应对施加哪些约束来控制数据质量”
      定义数据质量约束，对应功能：配置数据质量约束
  6、 “数据资产应该如何被利用”
      定义数据资产如何做数据分析
      6.1 本体构建
      6.2 本体探索
      6.3 数据分析
          6.3.1 因果分析
          6.3.2 根因识别
  7、 “用户完成其任务所需的自动化措施”
      定义用户完成任务所需的自动化措施，对应功能：自动执行分析过程
  8、 “定义角色和权限”
      定义该分析项目面向的用户角色，以及每个角色的权限

页面设计
  1、有一个项目列表，用户可以在列表中查看所有已创建的项目，已经创建分析项目
  2、在创建项目的页面，用户按照上述的步骤 2～8进行配置
  3、最后展示一个分析流程，分析流程是一个可视化的流程图，展示了2～6的过程
